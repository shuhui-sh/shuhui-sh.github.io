## 1. 软件概述

### 1.1 什么是 Clash Verge Rev？

Clash Verge Rev 是一个**开源、跨平台**的代理客户端 GUI（图形用户界面），基于 [Tauri](https://tauri.app/) 框架构建，支持 **Windows、macOS 和 Linux**。它是 Clash for Windows 的社区继任者（CFW 已于 2023 年底停止维护）。

### 1.2 架构原理

Clash Verge Rev 本质上是一个**图形化壳层**（Shell），负责提供用户界面和配置管理，底层代理功能由 **Mihomo 内核**（即 Clash Meta）驱动：

```
┌─────────────────────────────────┐
│   Clash Verge Rev (GUI 壳层)     │
│   - 用户界面                      │
│   - 订阅管理                      │
│   - 配置编辑                      │
│   - 系统代理/防火墙设置            │
└──────────┬──────────────────────┘
           │ 进程管理（service mode）
┌──────────▼──────────────────────┐
│    Mihomo 内核 (Clash Meta)      │
│   - 流量代理                      │
│   - 规则匹配                      │
│   - DNS 解析                      │
│   - 协议支持                      │
└─────────────────────────────────┘
```

### 1.3 核心优势

| 对比维度 | Clash for Windows | Clash Verge Rev |
|---------|:---:|:---:|
| 维护状态 | ❌ 2023年停更 | ✅ 持续更新 |
| GUI 框架 | Electron（资源占用大） | Tauri（轻量，基于 Rust） |
| 内核 | Clash Premium（停更） | Mihomo / Clash Meta（活跃） |
| 订阅绕过代理 | ❌ 不支持 | ✅ 支持（解决 403 问题） |
| 订阅自动更新 | ❌ 手动 | ✅ 定时自动 |
| 代理守护 | ❌ 不支持 | ✅ 防篡改 |
| WebDAV 备份 | ❌ 不支持 | ✅ 云端同步配置 |
| 自定义 CSS/主题 | ❌ 有限 | ✅ CSS 注入 |
| URL Schemes | ❌ 不支持 | ✅ 外部唤起 |
| Win7 支持 | ✅ | ❌ 仅支持 Win10+ |

### 1.4 协议支持

通过 Mihomo 内核，支持以下代理协议：

- **Shadowsocks**（SS）
- **VMess / VLESS**
- **Trojan**
- **Hysteria / Hysteria2**
- **TUIC**
- **WireGuard**
- **HTTP / SOCKS5**

## 2. 下载与安装

### 2.1 下载

**Release 页面**：https://github.com/clash-verge-rev/clash-verge-rev/releases

Windows 提供两种包：

| 安装包类型 | 文件名模式 | 适用场景 |
|-----------|-----------|---------|
| **setup.exe** | `Clash.Verge_2.5.1_x64-setup.exe` | 标准安装，创建开始菜单和桌面快捷方式 |
| **portable.zip** | `Clash.Verge_2.5.1_x64_portable.zip` | 便携版，解压即用，数据存放在程序目录 |

此外还提供**内置 Webview2 的安装版**（文件较大），适用于企业版 Windows 或无法安装 Webview2 运行时的环境。

### 2.2 Windows 安装

#### 安装版
1. 下载 `Clash.Verge_2.5.1_x64-setup.exe`
2. 双击运行，按向导完成安装
3. 首次启动时会自动安装**服务模式**，需同意 UAC 提权

#### 便携版
1. 下载 `Clash.Verge_2.5.1_x64_portable.zip`
2. 解压到任意目录（如 `D:\Tools\ClashVerge`）
3. 运行 `Clash Verge.exe` 即可

### 2.3 系统要求

| 平台 | 最低版本 |
|------|---------|
| Windows | Windows 10 及以上（不再支持 Win7） |
| macOS | macOS 11+ (Apple M / Intel) |
| Linux | Debian/Ubuntu (DEB) 或 Red Hat/Fedora (RPM) |

## 4. 订阅管理

订阅功能位于 **「订阅」** 页面，是日常使用最频繁的功能。

### 4.1 添加订阅

1. 进入「订阅」页面
2. 点击右上角 **「新建」** 按钮
3. 填写配置信息：

| 字段 | 说明 |
|------|------|
| **名称** | 自定义名称，如「LinkCube」 |
| **URL** | 机场提供的订阅链接 |
| **类型** | Remote（远程）/ Local（本地文件） |
| **User-Agent** | 自定义 UA（可选，用于绕过服务端限制） |

4. 点击「确定」后，自动拉取节点配置

### 4.2 订阅特殊设置（解决 403 / Cloudflare 拦截）

这是一个对你有特殊意义的功能。部分机场的订阅链接由 Cloudflare WAF 保护，会检测代理流量并返回 403。

在订阅条目的右侧操作按钮中：

- **跳过服务器证书验证**：适用于自签名证书的订阅服务器
- **不使用系统代理下载**（推荐开启）：**订阅下载时绕过本地代理，直连下载** —— 这正是解决你遇到问题的关键选项

> ⚠️ **提示**：开启「不使用系统代理下载」时，需要你的网络能直连到订阅服务器。如果订阅服务器在国内无法直连，请先在手机上用流量下载配置，再导入到电脑。

### 4.3 订阅操作

每个订阅条目右侧提供以下操作按钮：

| 操作 | 功能 |
|------|------|
| 🔄 更新 | 重新拉取订阅配置 |
| ✏️ 编辑 | 修改订阅名称、URL、UA 等 |
| 📝 编辑规则 | 对当前订阅配置添加自定义分流规则 |
| 📂 查看 | 查看配置文件的原始内容 |
| 🗑️ 删除 | 删除该订阅 |

### 4.4 定时自动更新

在「设置」→「订阅设置」中，可以配置：

- **自动更新间隔**：每 N 分钟自动拉取订阅（建议 1440 分钟，即每天一次）
- **启动时更新**：软件启动后自动更新所有订阅

### 4.5 多订阅合并（进阶）

如果你有多个机场账号，可以将多个订阅合并为一个配置文件使用：

1. 在「订阅」页面添加所有订阅
2. 进入「设置」→「全局扩展配置」
3. 编写 Merge 脚本将多个订阅合并
4. 重启后生效

官方文档中有 Merge 脚本的写法和示例。

## 5. 代理模式

代理模式分为两个维度：**入站方式**（流量如何进入代理内核）和**出站方式**（流量如何离开代理内核）。

### 5.1 入站方式：系统代理 vs TUN 模式

#### 系统代理

| 属性 | 说明 |
|------|------|
| **原理** | 修改操作系统代理设置，应用程序**自觉**读取设置后通过代理发送流量 |
| **适用** | 浏览器、大部分桌面应用 |
| **不适用** | 命令行工具、游戏（UDP）、部分应用 |
| **UDP 支持** | ❌ 不支持 |
| **资源配置** | 极低 |

> 系统代理是**约定而非强制** —— 应用程序是否走代理取决于开发者是否遵守这个约定。

#### TUN 模式

| 属性 | 说明 |
|------|------|
| **原理** | 创建虚拟网卡，修改系统路由表，**从网络层拦截所有流量** |
| **适用** | 所有程序，包括命令行、游戏、UDP 应用 |
| **不适用** | 无（全覆盖） |
| **UDP 支持** | ✅ 支持 |
| **虚拟网卡默认堆栈** | GVisor |

> TUN 模式是**强制代理** —— 应用程序没有选择权，所有流量都会被拦截并交给内核处理。

### 5.2 何时使用 TUN 模式

| 场景 | 推荐模式 |
|------|---------|
| 日常浏览网页 | 系统代理 |
| 使用终端（curl、git、npm 等） | TUN 模式 |
| 玩外服游戏 | TUN 模式 |
| 所有流量都要经过代理 | TUN 模式 |
| 低配电脑（节省资源） | 系统代理 |

### 5.3 服务模式

TUN 模式需要**管理员权限**才能创建虚拟网卡。服务模式解决了这个问题：

- **安装**：首次启动时自动安装，需 UAC 确认
- **原理**：后台启动一个服务进程 `clash-verge-service`，由服务进程拉起内核，内核继承管理员权限
- **好处**：你无需以管理员身份运行主程序即可使用 TUN 模式
- **持久性**：退出 CVR 后，服务进程继续在后台运行

#### 服务模式故障排查

如果服务模式安装失败：

**Windows**：在 PowerShell（管理员）中执行：
```powershell
sc delete clash_verge_service
```
然后重启 CVR 重新安装。

**macOS/Linux**：在「设置」→「Clash 内核」中点击齿轮图标 ⚙️ →「授权」。

### 5.4 代理守护

在「设置」中开启代理守护后，Clash Verge Rev 会**持续监控系统代理设置**，如果被其他软件修改则自动恢复。防止代理意外失效。

## 6. 出站模式

出站模式决定流量到达代理内核后**通过哪条路径发出**。

### 6.1 规则模式（推荐）

根据配置文件中的规则/规则集进行**条件匹配**，按域名、IP、地理位置等维度分流：

```
流量到达 → 匹配规则
             ├── 国内网站/IP → 直连（DIRECT）
             ├── 国外网站/IP → 走代理节点
             └── 未匹配流量  → 走默认策略组
```

### 6.2 全局模式

所有流量**统一通过选定的代理节点**发出。

### 6.3 直连模式

所有流量**不经过代理**，直接从本地网络发出。

### 6.4 模式对比

| 模式 | 国内流量 | 国外流量 | 适用场景 |
|------|---------|---------|---------|
| 规则模式 | 直连 | 按规则分流 | ✅ **日常使用** |
| 全局模式 | 代理 | 代理 | 特殊需求（如全部走外网） |
| 直连模式 | 直连 | 直连 | 临时关闭代理 |

### 6.5 完整流量路径

```
┌──────────────────────────────────────────────┐
│  应用程序发出网络请求                           │
└─────────────────┬────────────────────────────┘
                  │
                  ▼
         ┌──────────────────┐
         │   入站控制         │
         │  系统代理 或 TUN   │
         └───────┬──────────┘
                 │
                 ▼
         ┌──────────────────┐
         │  Mihomo 内核     │
         │  规则匹配         │
         │  DNS 解析        │
         └───────┬──────────┘
                 │
                 ▼
         ┌──────────────────┐
         │   出站控制        │
         │  规则/全局/直连   │
         └───────┬──────────┘
                 │
                 ▼
         ┌──────────────────┐
         │  目标节点/本地网络 │
         └──────────────────┘
```

## 7. 节点与策略组

### 7.1 节点列表

在「代理」页面查看所有可用节点，信息包括：

- 节点名称（通常含地区标识，如 🇭🇰、🇯🇵、🇸🇬、🇺🇸）
- 实时延迟（ms）
- 协议类型

### 7.2 延迟测试

点击节点右侧的延迟数字或顶部「测速」按钮，可以测试节点延迟。

**延迟颜色含义**：
- 🟢 绿色：低延迟（通常 <300ms）
- 🟡 黄色：中等延迟
- 🔴 红色：高延迟或超时

### 7.3 策略组类型

| 策略组类型 | 行为说明 |
|-----------|---------|
| **手动选择 (select)** | 用户手动选定一个节点，始终使用该节点 |
| **自动选择 (url-test)** | 自动选择延迟最低的节点 |
| **故障转移 (fallback)** | 优先使用第一个节点，不可用时自动切换下一个 |
| **负载均衡 (load-balance)** | 在多个节点间分配流量 |

### 7.4 策略组图标

在「设置」中可以为每个策略组自定义图标，方便识别。支持内置图标包或自定义 URL 图标。

## 8. 规则配置

### 8.1 规则概述

规则是 Clash 分流的**核心机制**。每条规则由三部分组成：

```
规则类型, 匹配条件, 动作
DOMAIN-SUFFIX, google.com, PROXY
DOMAIN-KEYWORD, baidu, DIRECT
GEOIP, CN, DIRECT
MATCH, , PROXY
```

### 8.2 规则类型

| 规则类型 | 说明 | 示例 |
|---------|------|------|
| `DOMAIN` | 精确匹配域名 | `DOMAIN,www.google.com,PROXY` |
| `DOMAIN-SUFFIX` | 匹配域名后缀 | `DOMAIN-SUFFIX,google.com,PROXY` |
| `DOMAIN-KEYWORD` | 匹配域名关键词 | `DOMAIN-KEYWORD,google,PROXY` |
| `GEOIP` | IP 地理位置匹配 | `GEOIP,CN,DIRECT` |
| `IP-CIDR` | IP 网段匹配 | `IP-CIDR,10.0.0.0/8,DIRECT` |
| `PROCESS-NAME` | 进程名匹配 | `PROCESS-NAME,Telegram.exe,PROXY` |
| `RULE-SET` | 引用规则集 | `RULE-SET,my-rules,PROXY` |
| `MATCH` | 兜底规则（必须放在最后） | `MATCH,PROXY` |

### 8.3 编辑规则

#### 界面化方式（推荐新手）

1. 在「订阅」页面，右键订阅 →「编辑规则」
2. 按以下格式添加规则：
   ```yaml
   rules:
     - DOMAIN-SUFFIX,openai.com,PROXY
     - DOMAIN-SUFFIX,claude.ai,PROXY
     - PROCESS-NAME,WeChat.exe,DIRECT
   ```
3. 保存 → 重新开启代理开关生效

#### 脚本配置化方式（进阶）

通过「全局扩展脚本」实现更复杂的规则管理，适合有编程经验的用户。

### 8.4 规则集

规则集将多条规则打包成一个文件，通过 URL 远程加载，便于统一维护和分发：

```yaml
rule-providers:
  reject:
    type: http
    behavior: domain
    url: "https://cdn.jsdelivr.net/gh/Loyalsoldier/clash-rules@release/reject.txt"
    path: ./ruleset/reject.yaml
    interval: 86400
```

## 9. DNS 配置

### 9.1 DNS 在代理中的角色

DNS（域名解析）也是一个潜在的信息泄漏点。即使代理了流量，如果 DNS 查询走了国内 DNS 服务器，理论上可以看到你访问了哪些域名（即 **DNS 泄露**）。

### 9.2 推荐 DNS 配置

通过「全局扩展脚本」粘贴以下推荐配置（社区最佳实践）：

```yaml
dns:
  enable: true
  prefer-h3: true
  use-hosts: true
  use-system-hosts: true
  respect-rules: true
  listen: 0.0.0.0:1053
  ipv6: false
  enhanced-mode: fake-ip
  fake-ip-range: 198.18.0.1/16
  fake-ip-filter:
    - '*.lan'
    - '*.localdomain'
    - localhost.ptlogin2.qq.com
  default-nameserver:
    - 223.5.5.5
    - 119.29.29.29
  nameserver:
    - https://dns.alidns.com/dns-query
    - https://doh.pub/dns-query
  proxy-server-nameserver:
    - https://dns.alidns.com/dns-query
```

### 9.3 关键 DNS 参数说明

| 参数 | 说明 |
|------|------|
| `enhanced-mode: fake-ip` | 返回虚拟 IP，避免 DNS 泄漏 |
| `default-nameserver` | 解析 nameserver 域名时使用（**必须国内 DNS**，否则循环依赖） |
| `nameserver` | 普通域名解析用（走 DOH 加密 DNS） |
| `proxy-server-nameserver` | 解析代理节点域名用 |
| `fake-ip-range` | 虚拟 IP 地址范围 |

### 9.4 浏览器配套设置

为避免浏览器层面的 DNS 冲突：

1. **关闭浏览器安全 DNS**：
   - Chrome：`chrome://settings/security` → 关闭「使用安全 DNS」
   - Edge：`edge://settings/privacy` → 关闭「使用安全的 DNS 指定如何查找网站的网络地址」

2. **关闭 QUIC 协议**（可选，中国大陆网络环境推荐）：
   - 访问 `chrome://flags/#enable-quic`（Chrome）或 `about://flags/#enable-quic`（Edge）
   - 设为 `Disabled`，重启浏览器
   - 原因：中国大陆 ISP 限速 UDP，QUIC 协议反而成为负面增益

## 10. 连接管理

「连接」页面显示**当前活跃的代理连接**。

### 10.1 功能

| 功能 | 说明 |
|------|------|
| 实时列表 | 展示所有正在代理的连接 |

## 12. 进阶功能

### 12.1 链式代理

将多个代理节点串联起来，流量依次经过每个节点：

```
本机 → 节点A → 节点B → 目标网站
```

在「配置用例」→「链式代理」中有详细配置模板。

### 12.2 自定义脚本

通过编写 JavaScript 脚本实现代理行为的**编程化控制**，例如：
- 动态选择节点
- 自定义负载均衡策略
- 定时任务

### 12.3 URL Schemes 外部唤起

Clash Verge Rev 支持通过 URL Scheme 从外部唤起：
```
clash://install-config?url=<配置URL>
clash://install-subscription?url=<订阅URL>
```

### 12.4 CSS 注入自定义主题

在「设置」→「外观」→「CSS 注入」中编写自定义 CSS，实现个性化界面。

### 12.5 GeoData 更新

Clash Verge Rev 使用 GeoIP 和 GeoSite 数据进行地理位置分流。在设置中点击「更新 GeoData」可更新到最新版本。社区有精简版中国 IP 数据库（仅几百 KB），比官方 MaxMind 数据库（约 10MB）更轻量。

## 13. CFW 迁移指南

### 13.1 术语对照

| Clash for Windows | Clash Verge Rev |
|-------------------|-----------------|
| Profiles（配置） | 订阅 |
| Proxies（代理） | 代理 |
| General（通用） | 概述 |
| Connections（连接） | 连接 |
| Logs（日志） | 日志 |
| Mixin / Parser | 全局扩展脚本 |
| TAP 模式 | TUN 模式 |

### 13.2 迁移步骤

1. **导出 CFW 配置**（可选）
   - 在 CFW 中右键配置 → 导出
   - 或者直接复制 `C:\Users\<用户名>\.config\clash\profiles\` 目录下的 yaml 文件

2. **安装 Clash Verge Rev**
   - 不需要先卸载 CFW，两者可以共存

3. **导入订阅**
   - 打开 CVR →「订阅」→「新建」
   - 粘贴机场订阅链接
   - **重要**：勾选「不使用系统代理下载」以避免 Cloudflare 403

4. **导入配置文件**（如果有本地配置）
   - 将 CFW 的 yaml 配置文件拖入 CVR 或使用「新建」→ 类型选「Local」

5. **切换代理模式**
   - 在「概述」页或托盘菜单中切换到「规则」模式

6. **开启代理**
   - 系统代理：点一下开关即可
   - TUN 模式：设置中安装服务模式 → 开启 TUN

### 13.3 注意事项

- CFW 和 CVR **同时只能运行一个**（代理端口冲突，默认都是 7890）
- 如果想保留 CFW 作为备用，先退出 CVR 再启动 CFW 即可
- CVR 首次启动会自动安装服务模式（需 UAC 确认），这是正常行为

## 14. 常见问题

### Q1：订阅下载返回 403？

**问题**：订阅链接由 Cloudflare 保护，检测到代理流量后返回 403。  
**解决**：编辑订阅 → 开启「不使用系统代理下载」。

### Q2：TUN 模式无法开启？

**原因**：服务模式未成功安装。  
**解决**：
- Windows：管理员 PowerShell 中执行 `sc delete clash_verge_service`，重启 CVR
- macOS/Linux：设置 → Clash 内核 → 齿轮图标 → 授权

### Q3：开启代理后部分网站打不开？

**原因**：分流规则不完善。  
**解决**：
- 检查是否使用规则模式（推荐），而非全局模式
- 在订阅 → 编辑规则中为特定域名添加直连规则：
  ```yaml
  rules:
    - DOMAIN-SUFFIX,target-site.com,DIRECT
  ```

### Q4：DNS 泄露怎么检测和修复？

**检测**：访问 https://ipleak.net 或 https://www.dnsleaktest.com  
**修复**：
1. 确保开启 `enhanced-mode: fake-ip`
2. 关闭浏览器安全 DNS
3. 使用加密 DNS（DOH/DOT），而非明文 DNS

### Q5：Clash Verge Rev 和 CFW 可以同时运行吗？

**不可以**。两者默认都绑定同一端口（7890），会冲突。如需切换使用，退出一个再启动另一个。

### Q6：如何备份和恢复配置？

**WebDAV 同步**：在「设置」→「WebDAV 备份」中配置远程存储，可实现多设备配置同步。  
**手动备份**：右键托盘图标 →「打开目录」→ 复制整个应用目录。

### Q7：如何更新 GeoData？

设置 → 点击「更新 GeoData」，会自动下载最新 GeoIP 和 GeoSite 数据库。更新后建议重启应用。

### Q8：为什么有的节点延迟显示红色/-1ms？

节点不可用或协议不支持延迟测试。尝试手动切换到该节点看是否能正常使用。
